## Categories and filtering

All Work shows every project. Fixed filter order: Branding / Uniforms / Merchandise / Graphic / Photo & Videography.
Valid keys: `branding`, `uniforms`, `merchandise`, `graphic`, `photo-videography`.
Branding replaces the previous Identity filter key. A project can contain multiple keys;
matching any selected key includes it. Graphic and Photo & Videography currently have no projects
and show a short empty state. Do not invent categories based on placeholder image subject matter.

## Folder and naming rules

Use `public/images/portfolio/{primary-category}/{project-slug}/`.
Store a multi-category project's images only once, in its primary folder; its categories array
controls filters independently of the folder. Category folders are branding, uniforms, merchandise,
graphic and photo-videography. Earlier direct project folders remain empty reservations.
Current image paths still point to public/visuals; planned paths do not exist yet.

Use lowercase hyphens, no spaces, camera names or version suffixes.
Examples: project-name-cover.webp; project-name-detail-01.webp; project-name-branding-01.webp;
project-name-uniform-01.webp; project-name-merchandise-01.webp; project-name-graphic-01.webp;
project-name-photo-01.webp; project-name-video-cover-01.webp.
Video-cover files are still images; this task does not add a video player or video hosting.

## Adding a project

1. Add one object to portfolioProjects with slug, title, year (null if unknown), categories,
   categoryLabel, cover and images. Optional fields: services, client, location, description, seo.
2. Cover and image entries use the same shape as existing records: page, section, filename,
   currentSrc, plannedSrc, purpose, profile and alt. Keep page/folder/filename consistent.
   Use profile thumbnail for cover; projectHero for current Case Study figures.
3. categories may include several valid keys; categoryLabel is the concise card caption.
   Array order controls numbering and the first two Home Featured Work selections.
4. Add real assets only when approved. Run python scripts/optimize-images.py to register new
   raster files and generate responsive variants, then update their currentSrc paths.
   Until assets are supplied, use existing valid demo sources; do not add fake detail entries.
5. Route registration, static pages, sitemap entries and legacy /work redirects follow project data.
   Existing SEO metadata is preserved in each project's optional seo fields; new projects get defaults.
   npm run build regenerates exact Vercel project rules; review and commit vercel.json before deploying.
6. Run both guide generators, npm run build, npm run test:images and npm run test:seo.
   Validate the filters, case route and desktop/tablet/mobile crops. No filter-code edit is needed.
7. Commit data, originals, generated assets/manifests, guides and deployment route changes together.
